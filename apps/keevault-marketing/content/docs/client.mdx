title: "Client configuration"
description: "Configure the bootstrap client and launch your application."
---

keevault fetches an approved environment from the keevault control
plane and then replaces itself with your application. The application inherits
the decrypted secrets as ordinary environment variables. The bootstrap process
itself is gone by the time the application runs.

## Download and verify the client

On Linux, run this from your application's working directory:

```sh
curl -fsSL https://vault.keevault.my.id/download.sh | sh
```

The script selects the latest release for Linux amd64 or arm64, downloads it
from GitHub Releases, and compares its SHA-256 hash with the release catalog.
It saves an executable `./keevault` only after verification succeeds. A failed
download or hash check leaves an existing binary unchanged.

You need `curl` and either `sha256sum` or `shasum`. Other operating systems and
architectures are not supported by this downloader.

To choose a version, pass its published tag to the shell running the script:

```sh
curl -fsSL https://vault.keevault.my.id/download.sh | KEEVAULT_VER=v1.0.0 sh
```

Replace `v1.0.0` with a published version. An unset or empty `KEEVAULT_VER`, or
`KEEVAULT_VER=latest`, selects the highest published SemVer. The version belongs
to the `sh` process, so put it after the pipe as shown.

To inspect the script before running it:

```sh
curl -fsSL https://vault.keevault.my.id/download.sh -o download-keevault.sh
# Read download-keevault.sh before continuing.
sh download-keevault.sh
```

The hash verifies the binary against the catalog served by the control plane.
For builds that require an independently reviewed checksum, pin the release URL
and expected SHA-256 in your build configuration too.

## Configure your application

Create `keevault.json` in your application's working directory:

```json
{
  "vaultUrl": "https://keevault.example.com",
  "environmentId": "env_01ARZ3NDEKTSV4RRFFQ69G5FAV",
  "requiredSecrets": ["DATABASE_URL"],
  "command": ["npm", "run", "start"]
}
```

Set `VAULT_BOOTSTRAP_TOKEN` in your deployment's environment, then run:

```sh
./keevault
```

Keevault reads the application command from the JSON file. To change what runs,
edit `command`.
Keep the bootstrap token and secret values out of this file.

## JSON settings

| Field             | Purpose                                                                                                                                |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `vaultUrl`        | Your team's vault URL.                                                                                                                 |
| `environmentId`   | The environment you expect to receive. The client rejects approval for a different environment.                                        |
| `requiredSecrets` | Secret names your application needs. Startup fails if any are missing. Your application still receives all secrets in the environment. |
| `command`         | The executable and its arguments, as a nonempty array. For example, `["npm", "run", "start"]` or `["node", "server.js"]`.              |

The command runs directly without shell expansion. Relative paths resolve from
the working directory where you run keevault. Keep the config there too, or use
`KEEVAULT_CONFIG` to select another file.

Unknown fields, malformed JSON, duplicate or invalid secret names, and files
larger than 1 MiB fail at startup. Secret names must match
`^[A-Z_][A-Z0-9_]{0,255}$`.

When started, keevault requests access to the environment and waits for an
approval. If the connection drops, it retries automatically. Once approved,
it decrypts the secrets and runs your command with those environment variables.
See [approving a boot](/docs/approving-boots) for the dashboard steps.

The bootstrap client never returns 0 itself. After replacement, the application
controls the exit status and may exit 0.

## Docker

Use keevault as your image's entrypoint and keep the application command in
`keevault.json`. The [Docker guide](/docs/examples/docker) includes a complete Dockerfile,
Node app, and build and run commands.

## Exit codes

| Code | Meaning                                                                            |
| ---- | ---------------------------------------------------------------------------------- |
| 0    | Never returned by the bootstrap client; the launched application may return it.    |
| 2    | Configuration error, a missing required secret, or a command that cannot be found. |
| 3    | An administrator declined the boot.                                                |
| 4    | The boot expired, was canceled, or the pending timeout ran out.                    |
| 5    | Unrecoverable transport or protocol failure, including a rejected token.           |

## What is logged

All logging goes to stderr, one plain line at a time:

```text
boot request created: boot_01K4M4X31X2Z5G9C7Q8D3E6F4G
waiting for approval
reconnecting
approval received
environment decrypted (7 values)
starting application
```

Secret names, secret values, key material and the bootstrap token are never
logged at any level. `debug` adds connection and retry detail, still without
secret material.
