---
title: "Managing secrets"
description: "Organize environments, add secret values, and give an application access."
---

Use a project to group an application's environments. Keep production, staging,
and development in separate environments so each deployment gets only the
values intended for it.

## Add and update values

Open your project and environment, then choose the Secrets tab. Add the name
and value for each secret your application expects, such as `DATABASE_URL`.
Use uppercase names with letters, numbers, and underscores. A name must start
with a letter or underscore.

Stored values aren't displayed again. You can replace a value when a credential
changes. You can also import a `.env` file to add several values. Check the
result after an import; if a write fails, earlier entries may already be saved.

Changing a stored value does not update an application that is already running.
Restart it and approve the new boot to load the current environment.

## Create a bootstrap token

In the environment's Tokens tab, create a token with a label that identifies
the deployment. Copy the value immediately; it is shown once. Save it as
`VAULT_BOOTSTRAP_TOKEN` in your deployment's environment settings.

The token lets the application request that environment. Someone must still
approve each start. Do not put the token in `keevault.json`, source control,
or a container image.

## Remove access

Revoke a token when a deployment no longer needs access or a token is exposed.
Revocation prevents future requests and cancels live requests associated with
that token. It cannot remove secrets from an application that already received
them.

If an application credential is exposed, replace it at the service that issued
it, update the value in keevault, and restart the application. See
[security basics](/docs/security).

Creating and changing secrets or tokens requires an admin or owner account.
Sensitive actions may ask you to verify your passkey again.
