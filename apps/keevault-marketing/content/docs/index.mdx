Keevault stores your application's secrets and delivers them as environment
variables. The client requests access, waits for a human to approve the boot,
then starts your application with the approved environment. Your app reads its
variables as usual; it does not need a Keevault SDK.

## Start with your first application

Follow the [quickstart](/docs/getting-started) to add secrets, download the client,
configure a command, and approve its first start.

If you only need the binary, go to [Install the client](/docs/installation).
For a complete runnable example, choose your deployment below.

| Your application                            | Walkthrough                                           |
| ------------------------------------------- | ----------------------------------------------------- |
| A Node.js HTTP server on Linux              | [Node.js app](/docs/examples/nodejs)                  |
| A container, built from Linux or macOS      | [Docker](/docs/examples/docker)                       |
| A long-running process without an HTTP port | [Background worker](/docs/examples/background-worker) |

## Understand the three parts

| Part            | What it does                                                                              |
| --------------- | ----------------------------------------------------------------------------------------- |
| Environment     | Holds the secret values for one deployment, such as production or staging.                |
| Bootstrap token | Lets a client request access to one environment. It does not approve the request.         |
| Boot            | One attempt to start your application. Each restart or redeployment needs a new approval. |

A project groups related environments. An admin or owner manages secrets and
approves boots in the dashboard. The person deploying an application can ask a
teammate to approve it.

## Manage a running integration

[Manage secrets and access](/docs/managing-secrets) when values change or a
deployment no longer needs access. A running process keeps the values it already
received; restart and approve a new boot to load updated secrets.

[Approve boots](/docs/approving-boots) to review requests and troubleshoot a
client that is still waiting.
